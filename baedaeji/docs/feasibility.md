# 배대지 실현 가능성 분석

작성: 2026-08-17. 법률·세무 자문은 아님. 통신판매·관세·PG는 세무사·관세사·PG사 확인이 필요합니다.

## 1. 구상하신 흐름을 다시 쓰면

1. 웹 메인에 앞으로 알려 줄 **링크들을 배너**로 둔다.
2. 고객이 **회원가입**한다.
3. 배너 링크(영국 쇼핑몰)에 들어가 **상품을 장바구니에 담는다.**
4. 고객이 **1차 결제 버튼**을 누른다.
5. (AI/시스템이) 그 상품을 알아보고 **오늘 환율**을 붙여 원화를 계산한다.
6. **네이버페이 등 2차 결제 버튼**을 만든다.
7. 고객이 결제하면, 운영자에게 **그 고객의 장바구니 리스트**가 보이거나, **회사 계정으로 영국 몰에 로그인해서 같은 상품을 장바구니에 넣어** 영국에서 결제·배송한다.

핵심은 “한국 고객이 원화로 내고, 영국에서 대신 사서 보낸다”입니다. 한국에서 흔히 말하는 **구매대행**에 가깝고, 영국 창고 주소만 주고 고객이 직접 영국 몰에서 결제하게 하면 **배송대행**입니다. 두 가지는 법·돈·리스크가 다릅니다.

## 2. 한눈에 보는 실현 여부

| 구간 | 실현 | 메모 |
|------|------|------|
| 메인 배너 링크 | 가능 | 운영자가 URL만 주면 됨. 가장 쉬운 부분. |
| 회원가입 | 가능 | 이메일/카카오/네이버 로그인. 개인통관고유부호는 주문 때 받는 편이 안전. |
| 해외몰 장바구니를 이 사이트가 “읽는” 것 | **사실상 불가** | 브라우저 보안(다른 사이트 장바구니를 못 봄). iframe도 대부분 차단. |
| AI가 실시간으로 상품을 알아채는 것 | **운영 방식으로는 부적합** | 채팅 AI가 결제 파이프라인에 있으면 안 됨. 소프트웨어가 견적·주문을 처리해야 함. |
| 오늘자 GBP→KRW 환율 | 가능 | 한국수출입은행 Open API (`oapi.koreaexim.go.kr`). 주말/11시 전은 전 영업일. |
| 네이버페이 2차 결제 | **조건부로 가능** | 사업자·통신판매업·구매안전(에스크로)·PG/네이버페이 가맹·심사가 먼저. 버튼만 만들 수는 없음. |
| 결제 후 운영자에게 리스트 표시 | 가능하고 **이게 정석** | 주문 대시보드. |
| 회사 ID로 영국 몰 자동 로그인·장바구니 복제 | **하지 않는 것을 권장** | 약관 위반·계정 정지·2FA·봇 탐지. 사람이 대시보드 보고 구매하는 편이 안전. |
| 영국에서 결제 후 한국 배송 | 운영으로는 가능 | 영국 현지 결제·출고 능력이 있으면 경쟁 우위. 통관·반품은 별도 설계. |

**결론:** 사업 모델은 됩니다. 처음 그리신 “해외몰 장바구니 공유 + AI 인식 + 자동 재담기”만 빼고, **자사 사이트에 상품 링크를 담는 구매대행**으로 바꾸면 됩니다.

## 3. 막히는 지점 — 해외몰 장바구니를 못 읽는 이유

고객이 배너를 눌러 Selfridges, NET-A-PORTER 같은 사이트에 가면, 그 장바구니는 **그 쇼핑몰 서버와 그 브라우저 탭** 안에만 있습니다.

배대지 웹사이트(또는 Cursor AI)는 다음을 할 수 없습니다.

- 다른 도메인의 쿠키·장바구니를 읽기 (동일 출처 정책)
- 해외몰을 iframe으로 감싸서 안을 조작하기 (`X-Frame-Options` / CSP로 거의 막힘)
- 고객 PC에 설치되지 않은 상태로 해외몰에 로그인된 화면을 보기

그래서 “1차 결제 버튼”을 눌러도, 우리 서버에는 **담은 상품 목록이 존재하지 않습니다.** AI에게 “방금 그 고객이 뭘 담았는지 알아내라”고 해도 데이터가 없습니다.

가능한 우회는 아래뿐이고, 대부분 비용·리스크가 큽니다.

| 우회 | 평가 |
|------|------|
| 고객이 상품 URL을 우리 사이트에 붙여넣기 | **MVP로 권장.** 트렌비·오마이집형 구매대행과 같음. |
| 북마클릿 / 크롬 확장 “이 상품 담기” | 2단계. UX는 좋지만 스토어 심사·사이트별 파서 유지보수가 필요. |
| 고객이 스크린샷을 올림 | 비추천. OCR 오류, 사이즈·품번 누락. |
| 우리가 해외몰을 프록시로 미러링 | 비추천. 저작권·약관·보안·차단. |
| 영국 몰 API 공식 제휴 | 이상적이지만 초기에는 비현실적. |

**권장 고객 문장:**  
“영국 사이트에서 사고 싶은 상품 페이지를 연 뒤, 주소창 URL을 복사해 여기에 붙여 넣으세요.”

## 4. “회사 계정으로 같은 상품을 장바구니에 넣어 준다”에 대해

기술적으로 Playwright 같은 브라우저 자동화로 **시도**는 할 수 있습니다. 다만 초기 제품으로 넣으면 안 됩니다.

- Selfridges 약관: 플랫폼은 **개인 사용**, 상업적 사용 금지. 대량·재판매로 보이면 주문 거절.
- NET-A-PORTER 약관: 구매는 **personal or gift**, 상업적 재판매 금지. 한 주소로 대량 제한.
- Cloudflare, 기기 지문, 2FA, 일회용 이메일 탐지 → 자동화는 금방 막힘.
- 계정 하나 정지 = 당일 전 주문 멈춤.
- 고객 돈은 이미 받았는데 영국에서 결제가 실패하면 **환불·민원**이 바로 생김.

운영 정석은 이겁니다.

1. 주문 대시보드에 `상품 URL / 브랜드 / 품번 / 사이즈 / 색 / 수량 / 고객 메모`가 보임.
2. 영국에서 **사람이** (또는 나중에 반자동으로) 그 URL을 열고 재고를 확인한 뒤 결제.
3. 주문 상태를 `견적 → 입금완료 → 영국구매중 → 구매완료 → 출고 → 통관 → 국내배송`으로 고객에게 공개.

AI의 역할은 결제 버튼이 아니라, **운영자가 볼 주문 요약·품절 시 고객 안내문 초안** 정도입니다.

## 5. 1차 결제 / 2차 결제를 이렇게 바꾸세요

고객 입장에서 “1차 결제”는 **이미 돈을 낸 것**으로 들립니다. 실제로는 견적 요청입니다. 이름이 잘못되면 민원·전자상거래법 분쟁이 납니다.

권장 이름:

| 원래 표현 | 바꿀 표현 | 하는 일 |
|-----------|-----------|---------|
| 1차 결제 | **견적 확인** | 상품 목록 + 환율 + 수수료 + 예상 배송비 확정. 돈 이동 없음. |
| 2차 결제 | **원화 결제** | 네이버페이/토스 등으로 실제 청구. |
| (없음) | **잔금/추후 정산** | 실측 무게·관세가 견적과 다를 때. 초기에 정책을 미리 고지. |

견적은 **환율 잠금 시간**이 필요합니다. 예: 수출입은행 매매기준율 기준 12시간. 만료되면 재견적. 주말에는 금요일 환율.

금액 구성 예시 (구매대행):

```
원화 청구 ≈ (GBP 상품가 + 영국 내 배송/세금) × (환율 + 환전 마진)
           + 대행 수수료
           + 국제운송 예상
           + (선택) 한국 관세·부가세 예상 또는 “통관 후 별도”
```

실무에서는 많은 배대지가 **상품대금은 선결제, 국제배송비는 입고 후 무게로 후결제**합니다. 한 번에 받으면 과다/과소 청구가 생깁니다. 하이엔드 소량이면 선견적 풀패키지도 가능하지만, **품절·가격변동 시 전액 환불 정책**을 먼저 적어야 합니다.

## 6. 환율 — 기술적으로는 쉬운 편

한국수출입은행 환율 Open API:

- URL: `https://oapi.koreaexim.go.kr/site/program/financial/exchangeJSON`
- `cur_unit = GBP`, 보통 `deal_bas_r`(매매기준율), 송금 보낼 때는 `tts`가 더 현실적
- 2025-06 이후 도메인 `oapi.koreaexim.go.kr` (구 도메인은 2026-04-30 종료 예정)
- 비영업일·당일 11시 전 요청은 빈 값 → **직전 영업일 환율 캐시** 필수
- 일 1,000회 제한 → 서버에서 하루 1~2회만 받아 캐시

고객에게는 “한국수출입은행 매매기준율 + ○○% 환전 수수료”처럼 **산식을 공개**하는 것이 분쟁을 줄입니다. 숨기면 “오늘 환율이 아닌데?” 항의가 나옵니다.

## 7. 네이버페이 — 버튼이 아니라 가맹 사업

네이버페이는 두 갈래입니다.

- **결제형:** 자사 주문서 안에서 네이버페이를 결제수단으로 씀. 구매대행처럼 주문 규칙이 특이한 서비스에 맞음.
- **주문형:** 네이버 주문서·클레임 프로세스를 탐. 검수·상품 XML·배송 상태가 까다로움. Briq에 주문형 샌드박스 자리가 있지만, **배대지에 그대로 복사하면 안 됩니다.** 상품이 카탈로그 SKU가 아니라 URL 주문이어서 주문형 상품정보 연동이 잘 안 맞을 수 있음.

공통 선행:

1. 사업자등록 (업종코드 실무상 525105 해외직구대행 vs 525101 전자상거래소매 — **매출 인식이 달라 세무사 확인**)
2. 구매안전서비스(에스크로) 확인증
3. 정부24 **통신판매업 신고**
4. PG(토스페이먼츠 등) 또는 네이버페이 직가맹 + 1·2차 심사
5. 이용약관, 개인정보처리방침, 청약철회·국제반송비 고지

초기에는 **토스페이먼츠 같은 PG 한 곳으로 카드+간편결제**를 열고, 네이버페이는 그 위 허브형으로 붙이는 편이 빠릅니다. “네이버페이만”으로 시작하지 마세요.

## 8. 법·통관 (2026 기준, 반드시 전문가 확인)

이 서비스를 한국 고객 대상으로 열면 대략 아래가 따라옵니다.

- **전자상거래법:** 신원 고지, 청약철회(수령 후 원칙 7일). 구매대행이라고 청약철회를 막을 수 없음. 다만 단순 변심 시 **국제 반송비 소비자 부담**은 사전 고지하면 실무에서 씀. 공정위는 해외구매대행 사업자의 철회 방해·허위 표시를 실제로 제재한 사례가 있음.
- **관세청 전자상거래업자 등록:** 2026-06-05부터 전용 등록(UNI-PASS `unipass.customs.go.kr/ecb`). 구매대행·배송대행 모두 대상. 2026-08-15 전용 통관플랫폼에서 **전자상거래업자 부호** 기재가 필수로 설계됨. 오늘(2026-08-17) 시점이면 등록 여부를 바로 점검해야 함.
- **개인통관고유부호:** 고객에게 받아 통관. 민감정보에 가깝게 취급, 통관 후 파기 정책. 도용 방지 강화 중.
- **목록통관 vs 일반수입:** 금액·품목에 따라 관세/부가세. “관부가세 포함가”를 광고하면 계산 근거가 있어야 함.
- **수입 금지·위조·의약품·식품:** 대행 거부 목록을 사이트에 게시.
- **영국 몰 약관 vs 한국 대행:** 고객을 위한 개인 사용 대행인지, 재판매 재고인지에 따라 영국 계정 리스크가 달라짐. 하이엔드 소량 개인 대행이 상대적으로 안전.

영국에서 회사 카드로 사고 한국 주소로 보내면, **누가 수입자인지**(고객 vs 회사)에 따라 세금이 갈립니다. 이 한 줄은 관세사와 초기에 정해야 합니다.

## 9. 더 나은 제품 아이디어

구상은 “한국인이 영국 사이트 가격을 보고, 원화로 맡긴다”가 핵심입니다. 그걸 지키는 더 나은 형태:

### A. 권장 MVP — 링크 구매대행 (쇼핑몰형 대행)

1. 메인: 영국 스토어 배너 (운영자가 링크를 계속 추가).
2. 고객: 배너로 이동 → 상품 고름 → **URL을 배대지에 붙여넣기** → 사이즈/수량.
3. 서버: 페이지 제목·이미지·가격을 가져올 수 있으면 가져오고, 실패하면 고객이 직접 가격·옵션 입력.
4. 견적(환율 잠금) → 원화 결제 → 운영 대시보드 → 영국에서 수동 구매.

장점: 기술 리스크가 작고, 주문 데이터가 우리 DB에 있음.  
단점: URL 복사가 한 단계 더 있음. 북마클릿으로 나중에 줄임.

### B. 배송대행만 (몰테일형)

고객이 영국 몰에서 **직접 결제**하고, 배송지만 우리 영국 창고. 우리는 합포·국제배송·통관만.

장점: 상품대금 PG·품절 환불이 거의 없음. 영국 몰 약관과도 덜 충돌.  
단점: 고객이 해외 카드/VAT/사이즈를 직접 해결해야 함. “대신 사 주세요” 수요를 못 받음.

### C. 하이브리드 (영국 현지가 있으면 가장 강함)

- 메인 배너 = “이 몰들은 배송대행 주소로 보내도 됩니다” + 창고 주소·수취인 규칙.
- 같은 사이트에 “카드가 없거나 대행을 원하면 URL로 구매대행”.

한 창고로 두 매출이 들어옵니다. 영국에 사람이 있다는 점이 한국 순수 배대지 대비 강점입니다.

### D. 하지 말 것

- 해외몰 전체 상품을 우리 카탈로그로 긁어 파는 것 (Briq과 충돌하고, 재고·가격·이미지 권리 문제가 큼).
- 고객 해외몰 세션을 가로채는 브라우저 해킹성 툴.
- AI를 실시간 결제 승인자로 두는 것.

### E. 차별화 (Briq과 겹치지 않게)

Briq은 **이미 사입한 SKU를 한국몰처럼 파는** 모델입니다. 배대지는 **고객이 고른 영국 상품을 건건이 사오는** 모델입니다. 같은 영국 소싱이라도 재고 리스크가 반대입니다.

차별 포인트 후보:

- 영국 현지 검수 사진 (하자·정품 확인)
- 합포장, 슈박스 제거 등 부피 옵션
- 하이엔드 한정 — 명품 URL만, 식품·전자기기 거절
- 예상 관부가세 시뮬레이터
- 카카오 알림톡으로 상태 푸시

## 10. 운영 리스크 (기술보다 이쪽이 큼)

1. **결제 후 품절:** 전액 환불 자동화. 대체 상품은 고객 동의 후에만.
2. **가격 변동·세일 종료:** 견적 시점 스크린샷 또는 크롤한 가격을 주문에 저장.
3. **사이즈 실수:** 옵션을 필수 입력. 애매하면 구매 보류.
4. **반품:** 영국 14일 철회 vs 한국 7일 vs 국제 왕복비. 표로 약관에 고정.
5. **환율 손실:** 잠금 창 + 마진. 대규모면 선물환은 나중.
6. **계정 정지:** 구매 몰을 분산, 자동화 금지, 개인 사용 패턴 유지.
7. **PG 차지백:** 배송 증빙·트래킹을 주문에 붙임.
8. **개인정보:** 통관부호·여권번호(필요 시) 암호화, git 금지.

## 11. 권장 시스템 골격 (나중에 앱 만들 때)

```
고객 앱 (별도 Next.js, 별도 도메인)
  ├ 배너(스토어 링크 JSON)
  ├ 회원 (이메일/소셜)
  ├ 링크 장바구니
  ├ 견적 (환율 캐시 + 수수료 정책)
  └ 결제 (PG) → 주문

운영자 앱
  ├ 주문 큐 (고객별 라인아이템)
  ├ 상태 변경 + 고객 알림
  └ 환율·배너·수수료 설정

외부
  ├ 수출입은행 환율
  ├ PG / 네이버페이
  └ (통관) UNI-PASS 전자상거래업자 부호
```

데이터베이스는 주문·회원·배너가 있으므로 **서버 DB가 필요**합니다. Briq처럼 정적 JSON 카탈로그만으로는 부족합니다.

## 12. 단계별 현실성

| 단계 | 내용 | 난이도 |
|------|------|--------|
| 0. 지금 | 기획 문서, 배너 링크 수집, 사업자·관세 등록 체크 | 낮음 |
| 1 | 랜딩 + 회원가입 + URL 장바구니 + 수동 견적(관리자가 원화 입력) | 중 |
| 2 | 환율 API 자동 견적 + 운영 대시보드 | 중 |
| 3 | PG/네이버페이 실결제 | 중~높음 (심사·약관) |
| 4 | 북마클릿, 알림톡, 트래킹 | 중 |
| 5 | 특정 몰 가격 파서, 반자동 구매 보조 | 높음, 선택 |

단계 1만 되어도 “링크 주시면 견적 내 드립니다”를 웹으로 받을 수 있습니다. 네이버페이는 사업 준비가 끝나는 대로 붙입니다.

## 13. 최종 판단

- **실현 가능:** 배너, 회원, URL 장바구니, 환율 견적, PG 결제, 운영자 주문 리스트, 영국 수동 구매·배송.
- **그대로는 비권장/불가:** 해외몰 장바구니 자동 인식, AI가 2차 결제 버튼을 즉석 생성, 회사 계정 자동 로그인 후 장바구니 복제.
- **더 좋은 형태:** 구매대행(URL) + (여력 되면) 배송대행 창고 주소를 한 사이트에 두고, 결제는 견적 확정 후 한 번, 영국 구매는 사람이 대시보드를 보고 수행.
